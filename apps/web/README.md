# `apps/web` — Next.js frontend

Three surfaces in one app: the public information site, the resident portal, and the barangay
admin console. Same design tokens, deliberately different personalities
([`design.md`](../../docs/design.md) Section 8).

## Run it

From the **repository root**:

```bash
make dev
```

Then <http://localhost:8080> through the proxy, or <http://localhost:3000> direct.

| Command                                  | What it does                        |
| ---------------------------------------- | ----------------------------------- |
| `make shadcn`                            | Reinstall every shadcn/ui primitive |
| `npm run lint --workspace=apps/web`      | ESLint                              |
| `npm run format --workspace=apps/web`    | Prettier                            |
| `npm run typecheck --workspace=apps/web` | `tsc --noEmit`                      |
| `npm run build --workspace=apps/web`     | Production build                    |

`make lint` from the root runs lint, format check, and typecheck together — the same three CI
runs.

## Layout

```
src/
├── app/
│   ├── (public)/     landing, guides, hazard map, donate — ISR
│   ├── (auth)/       login, register
│   ├── (portal)/     resident — client-rendered, auth-guarded
│   └── (admin)/      console — client-rendered, role-guarded
├── components/
│   ├── ui/           shadcn primitives. Installed, not written. Do not edit
│   ├── common/       the app's own composites. This is what pages import
│   └── features/     domain components, mirroring the API's modules
├── lib/              api client, auth, brand constants
└── hooks/            TanStack Query hooks and small UI hooks
```

## Four things that will trip you up

1. **Never edit `components/ui/`.** `make shadcn` overwrites it. Token wiring goes in
   `globals.css`; app-specific styling goes in `components/common/` (NFR-MNT-006).
2. **Never import a `ui/` primitive into a page.** Pages import from `common/` or `features/`.
   The primitives are raw — a stock shadcn button is not `design.md`'s button.
3. **Design at 360px first.** Not "check it later on mobile". Two of the core flows — safety
   check-in and BHW field registration — are mobile-_first_, not mobile-tolerant
   (`design.md` Section 9.1).
4. **The access token lives in memory.** Never `localStorage`, never a non-httpOnly cookie
   (`architecture.md` A-5).
